## 2. 데이터 3단 분리 아키텍처 (`REQ-P0-06`)

- **계층 1 — 공개 매니페스트 (`SplitManifest`):** `sample_id`, `split_name`, `sha256`, `phash`, `sealed_level`만 포함하며 정답·작성자·클래스 복원 필드를 전면 금지한다.
- **계층 2 — 검증 전용 기밀 메타데이터 (`ValidationMetadataStore`):** `class_id`, `writer_id`, `alphabet_id`, `source_id`를 분리 저장하며 `OODValidator` 내부 검증에서만 사용한다.
- **계층 3 — 정답 저장소 (`GroundTruthVault`):** `ground_truth_vault.json`에 `sample_id → label`만 보관하며 공개 `get()`을 두지 않고 `LabelAccessPolicy` + `SealGuard`를 통과한 `resolve_labels()` 내부에서만 읽는다.
- **초기데이터 설계 통합:** `D12` 문서는 만들지 않는다. MNIST 원천 체크섬·10종 분할·Vault·검증 메타데이터·OOD 8쌍 생성 규칙은 `D4.md`와 이 문서에 통합한다.

## 3. Phase 0 비범위 경계 (`Non-Goals`)

- Phase 1~7 본체(F1~F4 풀링, GRU, DAS, World Model, Replay 엔진) 및 Phase 8~13(텍스트 어댑터, LLM 인터페이스, 웹 대시보드 UI)은 Phase 0에서 구현하지 않고 인터페이스 계약만 고정한다.
- Phase 0~7 기본 환경에는 LLM·텍스트 라이브러리를 설치하거나 import하지 않는다. 확장 의존성은 별도 optional dependency로 분리한다.

## 4. 연구 실험 사전 확정 기준 (`REQ-P0-10`)

- **데이터·분할:** `R3.md`의 `P0~P3`와 10종 split을 사용한다. `P1` 엄격 1-shot을 주 판정으로, `P0`/`P2`는 보조 기준으로, `P3`는 동일 도메인 상한 참고군으로만 사용하며 `H1~H6` 입증 근거에서 제외한다. support/query·OOD/transfer·공식/예비 봉인 분할의 격리 원칙은 `D4.md`와 2절을 따른다.
- **seed·에피소드:** split·episode·generator·model·stream_order 5종 seed를 실행 전에 설정하고 manifest에 기록한다. 사전학습은 3개 이상 seed, 예비 smoke는 최소 30 에피소드를 기준으로 하며 공식 표본 수는 비숫자 dev에서 측정한 분산으로 산정한다.
- **비교 조건:** 동일 입력·전처리·FP32 정밀도·에피소드·파라미터/관측 예산에서 비교한다. `quick_smoke`·`phase0_full_smoke`는 무튜닝으로 실행하고, P3와 엄격 1-shot을 혼합하지 않는다.
- **주 지표·MDE:** `v1.9.3:612-624`의 기준을 Phase 0 사전 등록 기준으로 확정한다.

| 가설 | 주 지표 | MDE / 제약 |
| :--- | :--- | :--- |
| `H1` | 동일 스텝에서 `Active − Fixed/Random` paired accuracy | `+3.0%p`, 동일 센서·비용 |
| `H2` | 스타일 변형 집합의 `A4 − 제안` accuracy 하락폭 감소 | `+3.0%p` 방어, 동일 파라미터 예산 |
| `H3` | `DAS − B4` 1-shot paired accuracy | `+3.0%p`, 동일 사전학습·support |
| `H4` | 동일 풀·예산에서 `R4_pool − R1_matched` paired accuracy | `+2.0%p`, 동일 풀·예산·Frozen |
| `H5` | 동일 예산의 AURC 상대 감소율 | `≥10%` 상대 감소, 셔플·누출 차단 |
| `H6` | 동일 목표 정확도의 관측 수·FLOPs 기반 비용 절감률 | `≥20%` 절감, 정확도 열등성 없음 |
| `H12-V` | `S5 − S1` 최종/평균 paired accuracy | `+3.0%p`, `S1 vs S2` 학습 확인 |
| `H13-V` | 기존 스타일·클래스 평균 망각 `F_t` | Dev에서 고정한 `F_t ≤ F_max` |
| `H15-V` | `S5 − S3/S4` macro recall 개선·혼동률 감소 | `+2.5%p`, `H13-V` 상한 충족 |

- **판정 규칙:** `SUPPORTED`는 Holm 보정 95% CI 하한 `>0`, 점추정치 `≥MDE`, 동반 제약 충족을 모두 만족할 때다. `NOT SUPPORTED`는 점추정치 `≤0`, CI 상한 `<MDE`, 동반 제약 위반 중 하나라도 해당할 때다. 그 외는 `판정 보류`(`INCONCLUSIVE`)로 기록한다.
- **기술 검증과 가설 판정 분리:** 재현성·격리·라벨 접근·NaN 0건·산출물 완전성·자원 상한 등 기술 수용 기준은 별도 `PASS/FAIL`로 판정하고, 가설 지지 여부와 혼합하지 않는다.
- **사전 등록 산출물:** 위 기준을 `experiments/preregistration_v1.9.3.md`로 3단계에서 구체화한다. 기준 변경은 공통 변경 통제 절차에 따른 승인이 필요하다.

## 5. 오픈소스 및 검증 한계

- `fvcore`은 FLOPs 보조 계측에만 사용하고, 파라미터 중복 제거·1B/4GB 판정·`unsupported_ops` 기록은 자체 계측기가 담당한다.
- `scikit-image`은 `B1` HOG 추출에만 사용하고 기준선 판정 규칙은 자체 구현한다.
- 잠금 파일은 설치 환경 스냅샷이므로 Python·플랫폼·CUDA가 달라지면 동일 재현성이 보장되지 않을 수 있다.
- CUDA 디바이스가 없는 환경에서는 실제 GPU 결정론·자원 계측을 완전히 검증할 수 없으며, GPU 환경 검증은 별도 증거로 유지한다.
